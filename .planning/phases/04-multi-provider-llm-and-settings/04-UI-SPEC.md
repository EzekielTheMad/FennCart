# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4: Multi-Provider LLM and Settings.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind CSS via CDN play build |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind components |
| Icon library | Heroicons (inline SVG, stroke, 1.5px stroke-width) |
| Font | ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif (system stack — no external font load) |

Source: `templates/base.html` body class and CDN script tags.

**No shadcn gate required.** This is a Python/Jinja2 SSR project; React-based component libraries do not apply.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact element spacing (`px-2 py-2`, `gap-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`) |
| lg | 24px | Card padding (`p-6`), section padding (`py-6`) |
| xl | 32px | Card padding — wizard style (`p-8`) |
| 2xl | 48px | Major section breaks (not yet used; reserve) |
| 3xl | 64px | Page-level spacing (not yet used; reserve) |

Exceptions:
- Sidebar nav items: `min-h-[44px]` touch target — overrides sm/md to meet 44px minimum.
- Settings sub-nav items must also use `min-h-[44px]` for consistency with main nav.

Source: `templates/base.html` nav items, `templates/setup/step_llm.html` card padding.

## Color

| Role | Tailwind Token | Hex (approx) | Usage |
|------|---------------|--------------|-------|
| Dominant (60%) | `slate-950` | #020617 | Page background (`bg-slate-950`) |
| Secondary (30%) | `slate-900` / `slate-800` | #0f172a / #1e293b | Sidebar (`bg-slate-900`), cards (`bg-slate-800`), form inputs (`bg-slate-700`) |
| Accent (10%) | `green-500` / `green-600` | #22c55e / #16a34a | Accent elements only (see reserved list below) |
| Destructive | `red-950` bg / `red-400` text / `red-800` border | — | Error states and destructive feedback only |

**Accent reserved for:**
1. Active nav item left border: `border-l-2 border-green-500`
2. Primary CTA buttons: `bg-green-600 hover:bg-green-700`
3. Loading spinner: `text-green-500`
4. Success confirmation messages: `bg-green-950 border-green-800 text-green-400`
5. Active settings sub-nav item left indicator (same pattern as main nav)

**Accent is NOT used for:** passive text, section headings, field labels, secondary buttons, informational states.

**Semantic states:**
- Success: `bg-green-950 border border-green-800` / `text-green-400`
- Error: `bg-red-950 border border-red-800` / `text-red-400`
- Info/neutral: `bg-slate-700 border border-slate-600` / `text-slate-400`
- Authorized (Kroger status): green success chip — `text-green-400`
- Not authorized (Kroger status): amber — `text-amber-400`

Source: `templates/base.html`, `templates/partials/error_block.html`, `templates/setup/step_store.html`.

## Component Inventory

All components below are extensions of existing patterns. No new components from scratch.

### Settings Shell (`templates/pages/settings.html`)

Two-column layout within the existing `base.html` main content block:

```
[Left sub-nav: 200px fixed] | [Right content area: flex-1]
```

- Sub-nav background: `bg-slate-900` (matches main sidebar)
- Sub-nav border: `border-r border-slate-700`
- Content area: `p-8` padding
- Active sub-nav item: `bg-slate-800 border-l-2 border-green-500 text-slate-100`
- Inactive sub-nav item: `text-slate-400 hover:bg-slate-800 hover:text-slate-100`
- Each sub-nav item: `min-h-[44px]` touch target, `flex items-center gap-3 px-3 rounded-md transition-colors`

HTMX target: `<div id="settings-content">` swaps section partial on sub-nav click.

### LLM Section (`templates/partials/settings/llm.html`)

Container: `bg-slate-800 rounded-lg border border-slate-700 p-8`

Fields in render order:
1. Provider dropdown — standard select styled `bg-slate-700 text-slate-100 border border-slate-600 rounded px-3 py-2 text-sm`
2. Model dropdown (Alpine.js, changes per provider) — same select style
3. Custom model text input — shown when `provider === 'ollama'` or custom option selected, `bg-slate-700 text-slate-100 border border-slate-600 rounded px-3 py-2 text-sm`, placeholder: `e.g. llama3, mistral`
4. API Key field (masked, eye-icon reveal) — `type="password"`, Alpine.js toggle, shown when `provider !== 'ollama'`
5. Ollama endpoint URL field — shown when `provider === 'ollama'`, `type="url"`, placeholder: `http://localhost:11434`
6. "Leave API key blank to keep current value" helper text — `text-xs text-slate-500`
7. "Test connection and save" CTA button

Success/error feedback rendered as inline partial swap on the same `#settings-content` div or a nested feedback div.

### API Key Field with Eye-Icon Reveal

Alpine.js pattern:
- Container: `x-data="{ show: false }"` wrapping a `relative` div
- Input: `:type="show ? 'text' : 'password'"`, full-width, standard field styling
- Toggle button: `absolute right-3 top-2` (8px — matches `sm` token), `text-slate-400 hover:text-slate-300`, `type="button"`, `:aria-label="show ? 'Hide API key' : 'Show API key'"`
- Icon: eye / eye-slash heroicon inline SVG, `w-5 h-5`

### Store Section (`templates/partials/settings/store.html`)

Reuses the zip search + store selection UI from `templates/setup/step_store.html`, parameterized for settings-specific endpoints (`/settings/search-stores`, `/settings/select-store`). Stores the current store name at top: `text-sm text-slate-300` with `font-semibold` store name inline.

### Account Section (`templates/partials/settings/account.html`)

Shows Kroger auth status badge and re-authorize button:
- Auth status row: label `text-sm text-slate-400` + status chip
- Authorized chip: `bg-green-950 border border-green-800 rounded px-2 py-0.5 text-xs font-semibold text-green-400`
- Not authorized chip: `bg-amber-950 border border-amber-800 rounded px-2 py-0.5 text-xs font-semibold text-amber-400`
- Re-authorize button: `bg-green-600 hover:bg-green-700 text-white font-semibold py-2 px-4 rounded` (same as primary CTA style)

### Preferences Section (`templates/partials/settings/preferences.html`)

Single toggle row for default review mode:
- Row layout: `flex items-center justify-between py-4 border-b border-slate-700`
- Label: `text-sm font-semibold text-slate-100`
- Description: `text-xs text-slate-500 mt-0.5`
- Toggle: Alpine.js checkbox or custom toggle styled to match dark theme — `bg-slate-700` off, `bg-green-600` on
- Save button: standard secondary button style `bg-slate-700 hover:bg-slate-600 text-slate-100 font-semibold py-2 px-4 rounded`

### Test-Connection Feedback

Inline feedback returned from HTMX POST — matches existing partial patterns:
- Success: `bg-green-950 border border-green-800 rounded p-3 text-green-400 text-sm` — "Provider updated successfully."
- Error: `bg-red-950 border border-red-800 rounded p-3 text-red-400 text-sm` — problem description + resolution hint
- Loading state: Alpine.js spinner button (matches `step_llm.html` pattern exactly: `animate-spin h-4 w-4` inside button)

## Interaction Contracts

### Provider Dropdown Change (D-01, D-02)

- Trigger: Alpine.js `x-model="provider"` on `<select>`
- Effect A: API key field `x-show="provider !== 'ollama'"` — hidden immediately for Ollama
- Effect B: Ollama endpoint field `x-show="provider === 'ollama'"` — shown immediately for Ollama
- Effect C: Model dropdown options re-render per provider via `<template x-if>` blocks (no server round-trip)
- No loading state — all client-side

### Custom Model Toggle (D-02)

- Trigger: Model dropdown selection of `__custom__` option, or `provider === 'ollama'`
- Effect: Custom model text input appears (`x-show`)
- Custom field `name="custom_model"` — backend uses this over `model` when non-empty

### Test Connection and Save (D-08)

- Trigger: Form submit `hx-post="/settings/save-llm"`
- Loading state: Button text swaps to spinner + "Testing..." (Alpine.js), button disabled
- On success: Inline success message rendered in section partial; button re-enabled
- On failure: Inline error message rendered; config NOT saved; button re-enabled
- No full-page reload — HTMX partial swap only

### Sub-Navigation Section Switch (D-05)

- Trigger: Click on sub-nav item (`hx-get="/settings/section/{section}"`)
- Target: `#settings-content` div, `hx-swap="innerHTML"`
- Active state: Server renders correct `active_section` context var; sub-nav re-renders active indicator
- No loading indicator needed — section partials are small, fast server renders

### Kroger Re-Authorize (D-07)

- Trigger: Click "Re-authorize with Kroger" button — `href="/auth/kroger/start?redirect_after=settings"`
- Alpine.js loading state on button: `@click="loading = true"` — button shows "Waiting for authorization..."
- Full browser redirect (not HTMX) — OAuth requires top-level navigation
- On return: Redirect to `/settings?section=account` (not `/tour`)

### API Key Reveal Toggle (D-09)

- Trigger: Click eye-icon button (`type="button"`, prevents form submit)
- Effect: `:type="show ? 'text' : 'password'"` on input field
- Icon swaps between eye / eye-slash SVG based on `show` state
- Accessibility: `:aria-label="show ? 'Hide API key' : 'Show API key'"` on toggle button
