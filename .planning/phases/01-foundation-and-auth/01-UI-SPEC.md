## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind CSS utility classes via CDN play build |
| Preset | not applicable |
| Component library | none — hand-authored HTML components in Jinja2 templates |
| Icon library | Heroicons 2.x via inline SVG (MIT license; no Node dependency) |
| Font | System font stack: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif` |

**Rationale:** The stack is Python/Jinja2/HTMX — shadcn is React-only and does not apply. Tailwind CDN play build is used in Phase 1 per RESEARCH.md. Heroicons ship as inline SVGs, requiring no build step or CDN script for icons.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Tailwind Class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `p-1` / `gap-1` | Icon gaps, badge padding, tight inline spacing |
| sm | 8px | `p-2` / `gap-2` | Input padding, compact element spacing |
| md | 16px | `p-4` / `gap-4` | Default element spacing, form field gaps |
| lg | 24px | `p-6` / `gap-6` | Card/panel padding, section spacing |
| xl | 32px | `p-8` / `gap-8` | Wizard step container padding |
| 2xl | 48px | `py-12` | Major section breaks, page-level vertical rhythm |
| 3xl | 64px | `py-16` | Top-of-page breathing room on wizard and tour screens |

Exceptions:
- Touch targets for nav links: minimum 44px height (`min-h-[44px]`) per WCAG 2.5.5, even though 44 is not a standard scale step.
- Wizard step indicator dots: 12px diameter (`w-3 h-3`) — intentionally off-scale for a compact visual indicator.

## Color

The palette uses Tailwind's built-in slate and green scales. No custom hex values — all colors are Tailwind utility classes referencing the default palette.

| Role | Tailwind Tokens | Hex (light mode) | Usage |
|------|----------------|------------------|-------|
| Dominant (60%) | `bg-slate-950` / `bg-slate-900` | #020617 / #0f172a | Page background, wizard outer shell |
| Secondary (30%) | `bg-slate-800` / `bg-slate-700` | #1e293b / #334155 | Cards, nav, wizard step panels, input backgrounds |
| Accent (10%) | `bg-green-600` / `text-green-400` | #16a34a / #4ade80 | Reserved elements listed below |
| Destructive | `bg-red-600` / `text-red-400` | #dc2626 / #f87171 | Destructive actions and error states only |

**Accent reserved for (explicit list):**
1. Primary CTA buttons (e.g., "Continue", "Authorize with Kroger", "Complete Setup")
2. Active nav item indicator (left border or background highlight on current page)
3. Wizard step completion checkmarks
4. Connection test success indicators ("LLM connected", "Credentials valid")
5. Tour "Get Started" final CTA

**Accent is NOT used for:** links, hover states on non-CTA elements, informational text, icons in their default state.

**Text colors:**
- Primary text: `text-slate-100` on dark backgrounds
- Secondary/muted text: `text-slate-400`
- Input text: `text-slate-100` on `bg-slate-800`
- Placeholder text: `text-slate-500`
- Error text: `text-red-400`

**Dark mode only.** Phase 1 ships a single dark theme. Light mode support is deferred. No `dark:` class variants needed — everything is dark by default.

## Interaction Contracts

### Error UX Pattern

**Decision (Claude's discretion):** Use **inline contextual errors** for all validation within the wizard, and a **non-dismissable banner** for application-level errors (missing config page). Toasts are not used in Phase 1 — HTMX partial swaps replace the error target directly.

| Context | Pattern | Implementation |
|---------|---------|----------------|
| Wizard step validation (field-level) | Inline error below the field | HTMX swaps `#step-content` with the same step re-rendered with error state; error text in `text-red-400 text-sm mt-1` |
| Wizard step async validation (API call) | In-place loading → success/fail within the same step | Alpine.js `x-data` manages a `validating` boolean; spinner shown during validation; result replaces the validation button area |
| Missing config page | Full-page informational layout, not dismissable | Static Jinja2 render; no interactive elements beyond what is listed |
| OAuth callback error | Dedicated error state within `/setup/step_oauth` | HTMX re-renders the step with error message and a retry button |
| Network/server error (5xx) | Inline error injected into `hx-target` | HTMX `hx-swap-oob` injects a `#error-banner` at top of page; auto-dismissed after 8 seconds via Alpine.js |

### Navigation Structure

**Decision (Claude's discretion):** **Left sidebar**, fixed position, collapsed to icon-only on narrow viewports.

Rationale: FennCart will have 4-5 top-level destinations (Shopping, Preferences, History, Settings). A top nav bar compresses poorly at those counts and leaves primary content with no persistent context. A sidebar is the standard pattern for single-user utility apps with 4-8 navigation items. HTMX navigates between pages via full page loads (not AJAX), so no client-side router is needed.

| Sidebar property | Value |
|-----------------|-------|
| Width | 240px expanded, 64px icon-only (at `lg:` breakpoint) |
| Background | `bg-slate-900` |
| Border | `border-r border-slate-700` |
| Active item | `bg-slate-800 border-l-2 border-green-500 text-slate-100` |
| Inactive item | `text-slate-400 hover:bg-slate-800 hover:text-slate-100` |
| App name/logo | Top of sidebar: "FennCart" in `text-lg font-semibold text-slate-100` |

### Wizard Step Indicator

| Property | Value |
|----------|-------|
| Layout | Horizontal row of 4 steps, centered above step content |
| Completed step | Green filled circle (`bg-green-600 w-3 h-3 rounded-full`) + connecting line |
| Active step | White/slate-100 filled circle + step label visible |
| Upcoming step | `bg-slate-700 w-3 h-3 rounded-full` + connecting line |
| Step label | `text-xs text-slate-400` below each indicator dot |

### Loading States

| Pattern | When | Implementation |
|---------|------|----------------|
| Button spinner | Any async validation (LLM test, Kroger API key check, zip search) | Alpine.js `x-data="{ loading: false }"` toggles button text/icon; button disabled during load |
| Skeleton placeholder | Not used in Phase 1 — no lists or data tables yet | N/A |
| HTMX indicator | For HTMX-triggered partial swaps | `htmx-indicator` class on a spinner element; shown automatically during HTMX requests |

## Registry Safety

No shadcn and no third-party component registries are used in this phase. All UI is hand-authored Jinja2/HTML + Tailwind utility classes.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none — not applicable (Jinja2 stack) | not required |
| Third-party | none | not required |

CDN dependencies loaded via `<script>` / `<link>` tags in `base.html`:

| Dependency | Source | Version | Risk |
|------------|--------|---------|------|
| HTMX | `unpkg.com/htmx.org` | 1.9.x | CDN integrity hash required (`integrity` attribute + `crossorigin`) |
| Alpine.js | `cdn.jsdelivr.net/npm/alpinejs` | 3.x | CDN integrity hash required |
| Tailwind CSS play CDN | `cdn.tailwindcss.com` | 3.x | Development only — replaced by purged `output.css` in Docker prod build |

**Action required during implementation:** Add `integrity` + `crossorigin="anonymous"` SRI attributes to all CDN `<script>` and `<link>` tags. Use https://www.srihash.org to generate hashes for the pinned versions.
