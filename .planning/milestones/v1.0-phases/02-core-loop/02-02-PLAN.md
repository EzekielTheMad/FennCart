**Function 1: `parse_shopping_list()`**
```python
import instructor
from app.schemas.shopping import ParsedListItem, ProductCandidate, ItemMatch, MatchResult

class ParsedList(BaseModel):
    """Wrapper for Instructor to return a list of parsed items."""
    items: list[ParsedListItem]

async def parse_shopping_list(
    raw_text: str,
    api_key: str,
    provider: str = "anthropic",
    model: str = "claude-3-haiku-20240307",
) -> list[ParsedListItem]:
```
- Use Instructor with LiteLLM to parse raw shopping list text into structured items.
- Build model string: `model_str = f"{provider}/{model}" if "/" not in model else model`
- Create Instructor client: `client = instructor.from_provider(f"litellm/{model_str}", async_client=True)`
- System prompt: `"You are a shopping list parser. Extract each item from the user's grocery list. For each item, identify the product name, quantity (default 1), unit if specified, and any notes (brand preferences, size, style). Handle natural language like 'a dozen eggs' (quantity=12, name='eggs') or '2% milk' (name='milk', notes='2% fat')."`
- User message: the raw_text
- Call `client.create(messages=[...], response_model=ParsedList, max_tokens=1000, max_retries=2)` and set `api_key` via `litellm.api_key = api_key` before the call (then restore after, or use a context pattern).

Actually, for LiteLLM, set the API key via environment-style: before calling create, do `import os; os.environ[_provider_env_key(provider)] = api_key` where `_provider_env_key` maps `"anthropic"` -> `"ANTHROPIC_API_KEY"`, `"openai"` -> `"OPENAI_API_KEY"`, `"ollama"` -> no key needed. This matches how LiteLLM discovers keys. Alternatively, pass `api_key=api_key` as a kwarg to `client.create()` if Instructor supports it — test both approaches. The simplest approach: since `test_connection` already uses `litellm.acompletion(api_key=api_key)`, check if Instructor's `client.create()` also accepts `api_key`. If not, set `litellm.api_key = api_key` before the call.

Return `result.items` (list of ParsedListItem).

On any exception from Instructor/LiteLLM, catch and re-raise as `RuntimeError(f"Failed to parse shopping list: {str(e)}")`.

**Function 2: `match_products()`**
```python
async def match_products(
    list_items: list[ParsedListItem],
    candidates: dict[str, list[ProductCandidate]],
    api_key: str,
    provider: str = "anthropic",
    model: str = "claude-3-haiku-20240307",
    preferences: Optional[dict] = None,
) -> MatchResult:
```
- Uses Instructor to select the best Kroger product for each shopping list item from the provided candidates.
- Per D-07: `preferences` parameter exists but is `None` in Phase 2 — the function signature is ready for Phase 3.
- Build model string same as parse_shopping_list.
- Create Instructor client same pattern.
- System prompt: `"You are a grocery product matching assistant. For each item in the shopping list, select the best matching product from the provided Kroger search results. Consider brand, size, price, and the user's notes. Rate your confidence from 0.0 to 1.0 — use 0.8+ only when the match is clearly correct. For items with ambiguous matches (generic descriptions, multiple plausible options), rate confidence below 0.8. Always provide 2-4 alternative UPCs when available."` If preferences is not None, append: `"\n\nUser preferences: {json.dumps(preferences)}. Prefer products matching these preferences."`
- User message: build with `_build_matching_prompt(list_items, candidates)` helper function. Format: for each item, show `"Item: {item.name} (qty: {item.quantity}{', notes: ' + item.notes if item.notes else ''})\nCandidates:\n"` then for each candidate: `"  - UPC: {c.upc} | {c.brand} {c.description} | {c.size} | ${c.price_regular or 'N/A'}\n"`. This keeps the prompt compact to manage token budget (per Pitfall 6). Do NOT include thumbnail_url or other display-only fields in the prompt.
- Call `client.create(messages=[...], response_model=MatchResult, max_tokens=2000, max_retries=2)`
- Return the MatchResult directly.
- On any exception, catch and re-raise as `RuntimeError(f"Product matching failed: {str(e)}")`.
